## はじめに

開発プロセスにおいて、Issueの起票やPull Request（PR）の作成は避けて通れない作業です。しかし、一つひとつ手動で行うのは意外と時間がかかり、面倒に感じることも多いのではないでしょうか。

「仕様は固まっているのに、チケットを何個も作って、ブランチを切って、コードを書いて、PRに説明を書いて……」

そんな作業、**AIエージェントに丸投げしたくないですか？**

今回は、Googleの次世代IDE（プレビュー版）である**Google Antigravity**と、**GitHub MCP**を組み合わせることで、要件定義からPR作成までの流れをシームレスに自動化する方法を解説します。

## 結論：開発は「指示」して「レビュー」する時代へ

GitHub MCPを導入したAntigravityを使えば、以下のようなやり取りだけで開発が完結します。

> **私**: 「この仕様書（requirements.md）に基づいて、Issueを切り分けて実装、PRの作成までやっておいて。」
> **エージェント**: 「承知しました。Issueを3つ作成し、それぞれブランチを作成して実装を行い、PRを作成しました。」

これが、今回実現するゴールです。

![自動化フローのイメージ](/images/automate-issue-to-pr/flow.png)

## 準備：環境を整える

まずは、AntigravityでGitHubを操作できるようにするために、**Github MCP (Model Context Protocol)** サーバーをセットアップします。

### 1. GitHub個人アクセストークン（PAT）の発行

GitHubの設定から、`repo` スコープを持つPATを発行しておきます。

### 2. GitHub MCPのインストール

Antigravityの設定（または `.agent/config` 等）で、GitHub MCPを追加します。
通常、以下のようなコマンドで動作します。

```bash
npx -y @modelcontextprotocol/server-github
```

:::message
**セキュリティの注意点**
トークンなどの機密情報は、直接コードに埋め込まず、環境変数やセキュアな設定ファイルで管理するようにしましょう。
:::

## 実践：自動化のワークフロー

環境が整ったら、実際に自動化を試してみましょう。

### ステップ1：要件定義の共有

まず、プロジェクトのルートに `requirements.md` などのファイルを作成し、実装したい機能を記述します。

```markdown:requirements.md
# 新機能：ログイン通知機能
- ユーザーがログインした際、Slackに通知を飛ばす
- 通知内容にはユーザー名とログイン時刻を含める
```

### ステップ2：エージェントへの指示

Antigravityのチャット欄で、エージェント（Antigravity）に指示を出します。

> 「`requirements.md` の内容を確認して。GitHub MCPを使って、このタスクを適切な単位でIssueとして起票し、その後、一つずつ実装してPRまで出してください。」

### ステップ3：エージェントの自走

ここから先は、エージェントが「思考」し、ツールを駆使して自走します。

1. **Issue起票**: `github-mcp-server` の `issue_write` ツールを使用して、Issueを作成します。
2. **実装**: ローカルファイルを編集し、コードを書きます。
3. **コミット・プッシュ**: 必要に応じて `run_command` で `git` 操作を行い、ブランチをプッシュします。
4. **PR作成**: `create_pull_request` ツールでPRを作成し、実装内容のサマリーも自動で入力します。

### ステップ4：レビューとマージ

あなたは、エージェントが作成したPRをレビューするだけです。修正が必要ならチャットで指示を出し、問題なければマージします。

## 他に応用できそうなアイデア

この組み合わせは、Issue/PRの管理以外にも様々な活用が考えられます。

- **リリースノートの自動生成**: mainブランチの差分からリリースノートを作成し、GitHub Releaseを公開。
- **コードレビューの自動化**: 新しく作成されたPRに対して、エージェントが自動的にコメントを付けて指摘。
- **依存関係のアップデート**: ライブラリの更新を検知し、互換性を確認した上でPRを作成。
