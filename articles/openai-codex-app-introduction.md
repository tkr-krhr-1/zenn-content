## はじめに

最近、OpenAIから**Codex App**という新しいデスクトップアプリが登場しました。  
これまでAIコーディングツールといえば**Cursor**や**Claude Code**等が主流でしたが、このCodex Appはそれらとはまた違った立ち位置の「エンジニアリングエージェント」として設計されています。

本記事では、Codex Appを使って実際にアプリを作りながら、その特徴的な機能である**Work Tree**や**Scheduled Automations**が開発フローをどう変えるのか検証してみます。

![Codex Appのメイン画面](/images/codex/1.png)
*Codex Appのメイン画面。プロジェクトの全体像を把握しやすいインターフェースになっています*

## 概要

### Codex Appとは？

OpenAIが提供するプロフェッショナル向けのデスクトップアプリケーションです。  
単なるコード生成ツールではなく、プロジェクト全体を深く理解し、アーキテクチャレベルの提案や複雑なタスクの自律実行を得意としています。

### 特徴

Codex Appには、他のツールにはない機能が搭載されています。

- **Deep Context**:  
  プロジェクトの全ファイルを読み込み、依存関係や設計意図を深く理解した上で、整合性の取れたコードを提案します。

- **Work Tree (並列作業)**:  
  Git worktreeの仕組みを活用し、メインの作業を邪魔せずに裏で複数のエージェントを並列で走らせることができます。  
  例えば、「今の機能実装を続けながら、裏で別のエージェントにバグ修正やテスト作成を任せる」といったことが可能です。

- **Scheduled Automations (定期実行)**:  
  決まった時間にタスクを自動実行できます。  
  「毎朝依存関係をチェックする」「コミット後に自動コードレビューを行う」「古いIssueを整理する」といった定型業務を自動化できます。

### 他ツールとの比較

| ツール          | 特徴               | 得意なこと                             | 立ち位置                                                   |
| :-------------- | :----------------- | :------------------------------------- | :--------------------------------------------------------- |
| **Cursor**      | IDE統合型          | 高速な修正、補完、フロントエンド微調整 | **"Super Powered Editor"**<br>書きながら考える             |
| **Claude Code** | CLI/エージェント型 | 自律的なタスク実行、複数ファイル編集   | **"Autonomous Agent"**<br>コマンド操作も含めて任せる       |
| **Codex App**   | デスクトップApp    | 計画立案、並列実行(Work Trees)、自動化 | **"Engineering Manager + Worker"**<br>設計と並列作業に特化 |

Codex Appは、「自分で手を動かす」よりも「指示を出して動いてもらう」 ことに特化しており、特に大規模な変更や、設計から入るようなタスクで真価を発揮します。

## 準備

Codex Appの詳細は以下から確認できます。
https://openai.com/ja-JP/codex/

Codex Appを使用するには、以下の準備が必要です。

1.  **OpenAIアカウント**:  
    ChatGPT PlusやProなどの有料プランが必要になる場合があります（執筆時点での要件を確認してください）。
2.  **デスクトップアプリのインストール**:  
    macOS向けのアプリをダウンロードしてインストールします。Windows版も順次リリースされる予定です。
3.  **GitHubリポジトリの追加**:  
    Work Trees機能自体はローカルのGitリポジトリだけでも動作しますが、PR作成の自動化等を行うためには対象のプロジェクトをGitHub等のリモートリポジトリに追加（連携）しておくことを推奨します。

インストール後、アプリを立ち上げて対象のプロジェクトフォルダを開けば準備完了です。
Codexが自動的にプロジェクトのスキャンを開始し、数分でコンテキストを構築します。

## 実践

それでは、実際にReactで「Todoアプリ」を作りながら、Codex Appの真価を試してみます。
特に今回は、単純な実装だけでなく、Codexが得意とする**並列作業**と**自動化**に焦点を当てます。

### Step 1: 要件定義と計画（Deep Context）

まずはチャットで「モダンなReactのTodoアプリを作りたい」と伝えます。
Codexはプロジェクト構造を理解しているため、既存のUIコンポーネントがあればそれを再利用する提案をしてくれます。

#### 提案を作成してもらうためには、プラスアイコンをクリックして、Plan modeに切り替える必要があります。

![Codexによる計画画面](/images/codex/2.png)
*Plan modeでアーキテクチャ設計を提案してもらった様子。既存コンポーネントの再利用まで考慮されています*

このように、アーキテクチャレベルでの整合性を保った提案が得られます。

### Step 2: Work Tree での並列作業 (Background Testing)

ここからがCodexの本領発揮です。
メイン画面でTodoリストのUI実装を進めている最中に、ふと「テストも書かなきゃ」と思ったとします。

通常なら作業を中断してテストファイルを作るか、後回しにするところですが、Codexなら「裏でやっといて」が可能です。

1.  メインのチャットとは別に、新しい「Work Tree（タスク）」を立ち上げます。
2.  指示: 「今作っているTodoListコンポーネントの単体テストをJestで書いておいて」
3.  自分はそのままUI実装を続行。

![Work Treesの分割画面](/images/codex/3.png)
*メインの作業画面とは別に、サイドパネルでWork Treeが立ち上がり、並列でタスクが進行します*

裏では、CodexがGit worktreeを使って一時的な環境を作り、テストコードを実装・実行して検証まで行います。
完了すると通知が来るので、内容を確認してボタン一つでマージできます。

![テストコードの実装完了](/images/codex/4.png)
*裏で実行されていたテスト実装タスクが完了し、検証結果と共に通知が届いた様子*

### Step 3: Scheduled Automations (定期実行)

アプリが完成した後、運用フェーズで役立つのが Scheduled Automations です。
「毎日やるほどじゃないけど、たまにやりたいメンテナンス」を自動化できます。

今回はリファクタリングの定期実行を設定してみます。

1.  Automation設定画面を開く。
2.  トリガー: 「毎日 13:00」
3.  指示: 「リファクタリング: プロジェクト全体をスキャンし、不要な `console.log` の削除、未使用変数の削除、型定義の整理を行ってください。」
4.  テストを実行押下して動作を確認する

![Scheduled Automationの設定](/images/codex/5.png)
*毎日の定時実行タスクを設定する画面。ここでスクリプトやプロンプトを指定します*

これで、指定した時間にCodexがコードを綺麗にします。

![自動作成されたPull Request](/images/codex/6.png)
*実行されたAutomationによって実行されたリファクタリング*

## アイデア

Codex Appにはまだ他にも様々な可能性があります。

- **大規模なライブラリ移行**:  
  「Vue 2 から Vue 3 への移行」のような大規模な変更も、Deep ContextとWork Treesを使えば、少しずつ確実に進めることができます。
- **ドキュメントの自動生成**:  
  Automationで「毎週金曜日にコードとドキュメントの乖離をチェックし、修正案を出す」なども可能です。
- **新人エンジニアの教育係**:  
  Codexの提案するコードは「なぜそうするのか」という理由付けがしっかりしているため、コードレビューを通じて学ぶことができます。
